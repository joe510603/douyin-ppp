# 触达窗口行为 & 验证码处理

> 回答两个常见问题：
> **「页面不能缩小吗？」** —— 能，而且默认就**看得见**。
> **「必须在最前面才能操作吗？」** —— 不需要，触达全程在后台跑，不抢你的焦点。

---

## 一、窗口有三种模式

配置项：`outreach.window_mode`（配置页 →「抖音触达 → 触达浏览器窗口」）

| 模式 | 窗口位置 | 你能看到吗 | 抢焦点吗 |
|---|---|---|---|
| **background**（默认） | 摆在**屏幕右侧**，像个副面板 | **能看见** | **不抢**，跑完也不占着前台 |
| offscreen | 完全在屏幕外（`left=-1160`） | 看不见 | 不抢 |
| visible | 正常显示并置前 | 能看见 | 会抢（扫码登录用） |

> 用户需求原文：「chrome 的网页可以让我能看到，可以不用隐藏，
> 只是让它不在所有窗口最前面也能运行，并且不要一直弹到最前面」
> → 对应的就是默认的 **background** 模式。

### background 模式具体是什么

- 窗口贴在**主屏幕右半边**（宽约屏幕 42%，最多 1100px），左边留给你正常干活
- 启动时把**前台焦点还给你**，之后搜索 / 开主页 / 开作品 / 找评论框**都不会弹前台**
- 只有**撞验证码**时才主动把它叫到屏幕中间；你验证完之后，**焦点自动还回来**

实测（真实触达路径，只读动作，不发评论）：

```
起始前台: Microsoft Edge
   启动后          前台=Microsoft Edge
   搜索页          前台=Microsoft Edge
   打开主页        前台=Microsoft Edge
   打开作品页      前台=Microsoft Edge
   滚动/找评论框   前台=Microsoft Edge
窗口坐标: {'left': 1098, 'top': 40, 'width': 806, 'height': 860}
抢前台的动作: 无 ✅
```

### 为什么要用 CDP 挪窗口，不能用启动参数

`--window-position=-3200,-3200` 这种启动参数在 macOS 上**经常不生效**——
Chrome 的持久化 profile 会记住上次的窗口位置，直接把参数覆盖掉。
实测「屏幕外」和「不屏幕外」的窗口位置只差 **22 像素**，
也就是说触达跑的时候，那个窗口一直实实在在挡在屏幕左上角。

真正可靠的是 Chromium 调试协议：

```python
session = ctx.new_cdp_session(page)
wid = session.send("Browser.getWindowForTarget")["windowId"]
session.send("Browser.setWindowBounds", {"windowId": wid, "bounds": {...}})
```

> 实测坑：Chrome 偶尔**只接受「移动」不接「改尺寸」**。
> 所以 `place_in_background` 设完要**读回来核对**，不对就再来一次。

### 更隐蔽的一个坑：浏览器会抢走前台焦点

窗口摆到屏幕外**不等于**不影响你。浏览器一启动，macOS 就把前台应用换成它了——
哪怕那个窗口在屏幕外、什么都看不见。

后果比「窗口挡住屏幕」更阴：用户切回自己的窗口继续干活，看起来一切正常，
但**键盘输入全进了那个看不见的浏览器**——在文档里打的字一个字都存不下来。

所以「窗口不碍事」必须包含两件事，缺一不可：

1. 窗口摆在不挡事的位置（屏幕外 / 屏幕右侧）
2. **焦点还给用户**（打字进的是你自己的窗口）

现在的做法：启动浏览器前先记住前台是谁（`osascript` 问 System Events），
窗口摆好之后原样还回去；撞验证码处理完也再还一次。

### 怎么自己验一下

```bash
.venv/bin/python scripts/check_focus_realpath.py    # 真实路径会不会抢前台
.venv/bin/python scripts/check_window_offscreen.py  # offscreen 模式：藏/叫回/操作
```

## 二、触达停下来的三种情况

> 这三种**处理方式完全不同**，混为一谈会白跑一轮，或者让人干等一个不会来的希望。
> 以前只有「验证码」配了飞书通知，软风控停了却一声不吭——
> 用户在网页上只看到一行日志，既不知道发生了什么，也不知道该干什么。

| 类型 | 页面表现 | 能不能靠扫码解决 | 怎么办 |
|---|---|---|---|
| **要本人验证** | 弹「接收短信验证码」/「为确保是本人操作」 | **能**（扫码或短信都行） | 叫人 → 停下等人工验证 |
| **登录失效** | cookie 里没有 sessionid | **能** | 叫人 → 扫码登录 |
| **账号限流**（软风控） | 评论发出去不报错，但页面上看不到 | **不能** | 直接停 → 等抖音解封 |

### 「要本人验证」长什么样（2026-11-11 实测）

抖音发评论时会弹一个对话框：

> **接收短信验证码**
> 为确保是本人操作抖音账号，请输入当前手机号 187\*\*\*\*\*52 收到的短信验证码
> [请输入验证码] [获取验证码]　　　[取消] [验证]
> **使用原设备扫码**

底部那行「使用原设备扫码」就是**扫码验证**的入口——抖音同时提供短信和扫码两种。

平台自己的裁决接口 `passport/safe/query_decision/` 会明确写：

```json
{
  "account_flow": "verify",                                  ← 要验证，不是限流
  "verify_scene": "comment",
  "verify_ways": [
    {"mobile": "187******52", "verify_way": "mobile_sms_verify"},
    {"nickname": "江枫唱晚",   "verify_way": "qr_code_verify"}     ← 扫码
  ]
}
```

**这就是为什么必须读这个接口**：光看页面文案猜，很容易把「要验证」误判成「账号限流」
—— 而这两者的处置完全相反：验证有人能解决，限流等不来人。

### 验证完之后会自动接着跑

抖音是在点「发送」之后才弹验证框的，所以验证通过后有两种可能：
评论被自动提交了，或者还卡在那儿。

程序的处理：**先回查评论到底在不在**——
- 在 → 直接算成功（**不重复发**，重复评论是抖音的限流/封号风险）
- 不在 → 补发一次

⚠️ 验证通过后还必须**清掉「要验证」这个状态**。不清的话它会一直挂着，
下一条线索**刚开跑就被拦死**（2026-11-11 实测：验证完第 1 条，第 2 条在搜索阶段就停了）。
所以裁决状态是**带时间戳**的：只认 60 秒内刚判的，过期的不再拦人。

### 账号限流（软风控）

这是抖音另一招：页面不弹验证码、不提示「操作频繁」，
就是把你的评论静默吞掉。单次可能是偶发，连续 2 次就判定账号被限流。

这时候**扫码没用**——登录态是好的，是账号本身被限制了。真正的判断方法：
用抖音 App **手动**发一条评论，能发出去 = 触达这边还有点问题；
也发不出去 = 账号确实被限流，只能等抖音自己解封（通常几小时到一天）。

### 三种情况都会做的三件事

1. **飞书私聊通知你**（手机也有推送）——带上该干什么的完整指引
2. 网页上出现**醒目横幅**（不是一行日志），写清楚：发生了什么 / 扫码有没有用 / 下一步怎么办
3. 停手状态记在数据库里，**刷新页面、服务重启之后横幅还在**——
   你不一定记得十分钟前跑过一次，不能让你对着空气猜

   停手种类（`verify` / `limit` / `login`）**单独存一列** `outreach_runs.kind`，
   不靠 note 文案去猜。猜是猜不准的——实际写进去的文案有好几种：

   | 实际情况 | note 文案 | 含「验证码」？ | 含「限流」？ |
   |---|---|---|---|
   | 要本人验证 | 触发风控：抖音要求验证本人操作才能发评论（…） | ✗ | ✗ |
   | 要本人验证 | 触发风控：跳转到安全验证页 | ✗ | ✗ |
   | 账号限流 | 触发风控：页面提示：操作频繁 | ✗ | ✗ |
   | 账号限流 | 触发风控：连续 2 条评论发出去但页面看不到，判定账号被限流（软风控） | ✗ | ✓ |

   靠关键词猜的结果就是：**最常见的两种停手，服务一重启横幅就消失**。
   （老记录没有 `kind` 列，代码里留了按文案回退的判断，只给历史数据用。）

### 验证码的具体流程

1. 检测到验证码（`RiskControl` 异常）
2. **飞书私聊通知你**
3. 触达**暂停**等你，网页上出现橙色等待条
4. 你点等待条里的「**打开浏览器窗口**」→ 窗口回到屏幕中间并置前
5. 你在那个窗口里把短信/拖拽图形验证过掉
6. **验证完自动接着跑**（每 5 秒探一次页面，验证码没了就自动继续，
   不用再点「我验证好了，继续」）

等待超过 `captcha_wait_minutes`（默认 15 分钟）没人管 → 结束本轮，不无限挂着。

### 为什么要有「打开浏览器窗口」这个按钮

平时窗口藏在屏幕外（你看不见它）。撞验证码时如果只靠自动置前，
遇到「窗口压在别的窗口底下」「置前没生效」这类情况，你就永远找不到它。

所以给一个**手动叫出来**的入口：点一下，窗口立刻回到屏幕中间。
这个动作必须绕一圈发信号给 worker 线程——浏览器是那个线程里的 Playwright 对象，
sync API 不允许跨线程调用，主线程碰不了它。

### 通知发不出去也不影响流程

飞书没配好、lark-cli 挂了、token 过期了——这些都只会让通知发不出去，
**触达本身照常继续等**（网页上的等待条还在）。通知失败不会把触达搞挂。

## 二之二、声音：打开作品不放音

抖音的作品页是自动播放视频的，直接开进去会**突然出声**——吵人，还暴露「有人在看」。

两层防线：

| 层 | 做法 | 管什么 |
|----|------|--------|
| **JS 强制静音** | 改掉 `HTMLMediaElement.prototype.play`，播之前先 `muted = true`；再用 `MutationObserver` 盯着后续插入的媒体元素 | **保证没声音** |
| **网络层拦媒体** | 直接 abort 掉 `media` 类型的请求 | 省流量省 CPU（可选） |

为什么静音不能只靠拦请求：MediaSource / blob / 缓存里的音频照样能出声。
所以静音由 JS 兜底，拦请求只是优化项。

配置项 `outreach.block_media`（默认 `true`）只管「别下载视频」，
**关掉也不影响静音**。

实测（`scripts/check_comment_box_media.py`，真实 profile 打开真实作品）：

- 拦媒体 vs 不拦媒体，评论区 DOM 都正常渲染（`commentArea` 两组都是 True）
- 两组视频元素**都**是 `muted`（不拦媒体那组实测有 1 个视频正在播——那就是声音的来源）

## 三、配置项

```yaml
notify:
  lark_im_enabled: true                                    # 撞验证码时飞书私聊通知
  lark_im_open_id: ou_xxx                                  # 你的 open_id
  lark_im_identity: bot                                    # bot=应用发 / user=你自己发

outreach:
  window_mode: background      # background=看得见在右侧 / offscreen=藏起来 / visible=置前
  block_media: true             # 别下载视频（静音不靠它，JS 兜底）
  min_delay: 45                 # 两条之间最少等多少秒
  max_delay: 120                # 两条之间最多等多少秒
  captcha_wait_minutes: 15      # 撞验证码等人工验证多久
  captcha_bring_to_front: true  # 撞验证码时自动把窗口叫到屏幕中间
```

### 间隔可以当场调，不用每次去配置页

「抖音触达」页面顶部就有「**最小间隔(秒) / 最大间隔(秒)**」两个输入框，
**留空 = 用配置里的值**。填了就只对这一轮生效，不写回配置。

调小的代价：抖音更容易要求验证（发得越密越容易被盯上）。
保守起见建议单条间隔不低于 30 秒。

`lark_im_open_id` 从这里看：

```bash
lark-cli auth status
```

## 四、已知限制

- **锁屏 / 休眠会让 Chrome 被系统挂起**。触达跑到一半你把电脑睡了，
  浏览器会被冻结，唤醒后可能超时失败。建议别在跑触达时合盖休眠。
- **验证码还是要人过**。系统能做的只有「及时叫你 + 停下等你 + 把窗口叫出来」，
  短信验证码本身过不了。
- 窗口位置用 CDP 挪，是 Chromium 私有协议。升级 Playwright 后建议跑一遍
  `scripts/check_window_offscreen.py` 确认没变。
